## 1. 架构总览

### 1.1 分层与依赖方向

```
┌──────────────────────────────────────────────────────────┐
│  UI 层            streamlit_app.py                        │
├──────────────────────────────────────────────────────────┤
│  Agent 决策层      agent/react.py      ← 手写 ReAct        │
│                   agent/router.py      工具路由            │
│                   agent/executor.py    并行/超时/重试      │
│                   agent/memory.py      会话记忆            │
│                   agent/tools/*        8 个工具            │
├──────────────────────────────────────────────────────────┤
│  生成层            generation/prompts.py                  │
│                   generation/rag.py    流式 + 引用溯源     │
│                   generation/cache.py  语义缓存            │
│                   generation/fallback.py 降级策略          │
├──────────────────────────────────────────────────────────┤
│  检索层            retrieval/hybrid.py  三档编排           │
│                   retrieval/vectorstore.py  Chroma        │
│                   retrieval/bm25_index.py   BM25          │
│                   retrieval/fusion.py       ★ 手写 RRF    │
│                   retrieval/reranker.py     重排序         │
├──────────────────────────────────────────────────────────┤
│  数据层            ingest/loaders.py    多格式解析          │
│                   ingest/chunkers.py    三种分块            │

├──────────────────────────────────────────────────────────┤
│  公共设施          core/schemas.py      ★ 层间接口契约      │
│                   core/providers.py     ★ 外部服务抽象      │
│                   config.py             配置中心            │
├──────────────────────────────────────────────────────────┤
│  横切              observability/trace.py + metrics.py     │
└──────────────────────────────────────────────────────────┘
```

**硬性约束**：依赖只能向下。`retrieval` 不知道 `agent` 存在；`ingest` 不知道 `retrieval` 存在。因此每层都能独立测试、独立替换。

### 1.2 两条数据流

**入库（离线）**

```
文件 → load_document() → Document{pages[]}
     → strip_boilerplate() → 去页眉页脚
     → chunker.split() → List[Chunk]
     → vectorstore.upsert()  (Chroma，含 embedding 调用 + 磁盘缓存)
     → bm25_index.add()      (pickle 持久化)
```

**问答（在线）**

```
用户问题
  → router.classify()            # 规则预判，能短路就短路
  → [纯算术/时间] 直接调工具，跳过 LLM 推理
  → [其余] ReAct 循环
        Thought → Action → Observation
        Action=kb_search → hybrid.search(mode)
              ├─ vectorstore.query(top=20)  ┐
              └─ bm25.query(top=20)         ├─ rrf_fuse(k=60) → 20 条
                                            ┘
              └─ reranker.rerank(top_n=5)
        → prompts.build_rag_messages() → llm.stream()
        → 引用校验 → AgentResult
  → trace.record() + metrics.compute()
  → 前端渲染
```

## 2. 层间接口契约（`core/schemas.py`）

所有跨层通信只用这 9 个结构。这是全项目最重要的文件。

| 结构 | 字段 | 说明 |
|---|---|---|
| `Page` | `text, page_no` | `page_no` 从 1 开始，是引用溯源的基础 |
| `Document` | `doc_id, filename, filetype, pages[], meta{}, ingested_at` | `doc_id = sha256(内容)[:16]`，内容寻址 |
| `Chunk` | `chunk_id, doc_id, filename, page_no, seq, text, token_count` | `chunk_id = f"{doc_id}::{page_no}::{seq}"` |
| `ScoredChunk` | `chunk, score, source, rank` | `source ∈ {vector, bm25, rrf, rerank}` |
| `Citation` | `index, filename, page_no, chunk_id, snippet` | `index` 从 1 开始，对应答案里的 `[n]` |
| `Message` | `role, content, citations[]` | |
| `AgentStep` | `index, thought, action, action_input{}, observation, latency_ms, tokens, error` | 一步 ReAct |
| `AgentResult` | `answer, citations[], steps[], tokens{}, latency_ms{}, route, degraded` | 前端与评测的统一产出 |
| `RetrievalResult` | `chunks[], mode, latency_ms, degraded` | `degraded` 非空表示走了降级链路 |

辅助函数 `estimate_tokens(text) -> int`：CJK 一字一 token，其余按 `ceil(英文单词数 / 0.75)`。用于上下文预算与滑窗裁剪。

## 3. 外部 API 契约（`core/providers.py`）

三个抽象接口 + 各两套实现（真实 / mock）。上层只依赖抽象。

### 3.1 DeepSeek —— 生成

```
POST {DEEPSEEK_BASE_URL}/chat/completions     (OpenAI 兼容)
Authorization: Bearer {DEEPSEEK_API_KEY}

{
  "model": "deepseek-chat",
  "messages": [{"role": "system", "content": "..."},
               {"role": "user",   "content": "..."}],
  "temperature": 0.3,
  "top_p": 0.95,
  "max_tokens": 1500,
  "stream": true,
  "stream_options": {"include_usage": true}
}
```

> **`stream_options.include_usage` 是必须的。** 流式模式下 usage 默认不返回，而成本监控与评测都依赖它。响应末帧才带 `usage` 字段。

### 3.2 SiliconFlow —— 向量化

```
POST {SILICONFLOW_BASE_URL}/embeddings
Authorization: Bearer {SILICONFLOW_API_KEY}

{"model": "BAAI/bge-m3", "input": ["文本1", "文本2"], "encoding_format": "float"}

→ {"data": [{"index": 0, "embedding": [1024 个 float]}, ...],
   "usage": {"prompt_tokens": N, "total_tokens": N}}
```

要点：
- `bge-m3` 维度 **1024**，最大输入 **8192 token**；
- **必须按 `index` 回填**，不能假设响应顺序等于输入顺序；
- 分批 32 条（`EMBED_BATCH_SIZE`）；
- **磁盘缓存**：key 为 `sha256(text)`，存 `storage/cache/emb/{key}.npy`。重叠切分产生的重复文本不会重复计费。

### 3.3 SiliconFlow —— 重排序

```
POST {SILICONFLOW_BASE_URL}/rerank
Authorization: Bearer {SILICONFLOW_API_KEY}

{"model": "BAAI/bge-reranker-v2-m3",
 "query": "用户问题",
 "documents": ["候选片段1", "候选片段2"],
 "top_n": 5,
 "return_documents": false}

→ {"id": "...", "results": [{"index": 3, "relevance_score": 0.87}, ...]}
```

`return_documents=false` 压缩响应体——文本本地已有，用 `index` 回查即可。

### 3.4 Mock 实现（无 key 也能验证全链路）

| 类 | 机制 | 保证 |
|---|---|---|
| `MockEmbedding` | `sha256(文本)` 播种 → 1024 维伪随机向量 → L2 归一化 | 确定性（同文本同向量）、有区分度、余弦 == 点积 |
| `MockRerank` | 查询与文档的词元重合数 / `sqrt(文档词元数)` | 长度归一的确定性打分 |
| `MockLLM` | 固定话术；检测到 ReAct 协议要求时返回合法的 `Action: Finish` | Agent 在全 mock 下也能收敛 |

工厂函数 `get_llm()` / `get_embedder()` / `get_reranker()` 带 `lru_cache`，由 `settings.*_provider` 分派。

## 4. 各模块接口

### 4.1 `ingest/loaders.py`

```python
SUPPORTED_EXTS: set[str] = {".pdf", ".docx", ".txt", ".md"}
class LoadError(Exception): ...
make_doc_id(path: Path) -> str          # 分块读取算 sha256，避免大文件占内存
safe_filename(name: str) -> str
load_document(path: Path) -> Document
```

PDF 用 **PyMuPDF**（对双栏排版与表格的综合表现最优，且速度快于 pdfplumber）。DOCX 用 `python-docx`。任何解析异常统一包成 `LoadError`，不泄漏第三方堆栈。

### 4.2 `ingest/chunkers.py`

```python
class BaseChunker(ABC):
    def split(self, doc: Document) -> list[Chunk]: ...

FixedChunker(chunk_size, overlap)        # 按 token 估算硬切
RecursiveChunker(chunk_size, overlap)    # ★ 默认：按分隔符优先级递归降级
SemanticChunker(chunk_size, threshold, embed_fn)  # 相邻句向量余弦断点
get_chunker(strategy: str, **kw) -> BaseChunker
strip_boilerplate(pages: list[Page]) -> list[Page]
is_reference_section(text: str) -> bool
```

`RecursiveChunker` 的分隔符优先级：`["\n\n", "\n", "。", "！", "？", "；", ". ", "! ", "? ", " ", ""]`，最后一级空串做硬切兜底，保证超长无标点文本也能切且**不产生空 chunk**。

`strip_boilerplate`：统计跨页重复的首行/末行，出现率 > 60% 且为短行者判为页眉页脚。末行仅在「整行就是一个页码」时才是页脚候选——正文常出现在行尾，误删正文不可逆，漏删非数字页脚只是噪声，两类错误代价不对称。

### 4.3 `retrieval/vectorstore.py`

```python
VectorStore(persist_dir: Path, collection: str, embedder: EmbeddingProvider)
  .upsert(chunks: list[Chunk]) -> int          # 幂等，按 chunk_id 覆盖
  .document_exists(doc_id: str) -> bool
  .delete_document(doc_id: str) -> int
  .query(query: str, top_k: int) -> list[ScoredChunk]
  .list_documents() -> list[dict]
  .count() -> int
  .health() -> tuple[bool, str]
```

实现要点：
- `PersistentClient` + `get_or_create_collection(metadata={"hnsw:space": "cosine"})`；
- 相似度 `score = 1 - cosine_distance`；
- `page_no` 必须以 **int** 存进 metadata（引用溯源依赖它）；
- **空集合短路**：`count()==0` 直接返回 `[]`，省一次 embedding 调用；
- 单次写入按 512 分批（Chroma 单次 upsert 有上限）；
- **集合名兼容**：Chroma 1.5.x 要求名字 3-512 字符，非法名（如 `"t"`）确定性改写为 `f"{清洗后}-{sha1(名字)[:8]}"` 并 `logger.warning`，物理名通过 `self.collection_name` 暴露。

### 4.4 `retrieval/bm25_index.py`

```python
tokenize(text: str) -> list[str]     # 英文小写词 + 中文 bigram + 数字
BM25Index(index_dir: Path)
  .build(chunks) / .add(chunks) / .remove_document(doc_id)
  .query(query: str, top_k: int) -> list[ScoredChunk]
  .save() / .load() -> bool / .count()
```

- 中文用 **bigram**（无需 jieba，零额外依赖），英文取长度 ≥ 2 的小写词，数字单独保留；
- **不变量：得分 > 0 ⟺ 至少命中一个查询词元。** 因为 `BM25Okapi` 的 idf 在「词出现在恰好一半文档」或语料极小时会退化为 0（2 篇语料时任何词 idf = 0），严格过滤会丢掉真命中，故 score ≤ 0 时用命中词元数 × `1e-6` 兜底，再照旧过滤；
- 未选 `BM25Plus`：它给零命中文档也打正分，违背「不返回大量无关 chunk」的目标。

### 4.5 `retrieval/fusion.py` —— 手写 RRF

```python
rrf_fuse(result_lists, k=60, weights=None, top_k=None) -> list[ScoredChunk]
```

```
score(d) = Σ_i  w_i / (k + rank_i(d))
```

**为什么用 RRF 而不是分数加权求和**：BM25 分数无上界（随语料规模变化），余弦相似度在 [-1, 1]——两者量纲不可比。加权求和必须先归一化，而归一化方式（min-max / z-score）会引入额外超参且对异常值敏感。RRF 只用排名，天然免归一化、免调参。

### 4.6 `retrieval/reranker.py`

```python
Reranker(provider=None, enabled=True, min_relevance=None)
  .rerank(query, candidates, top_n) -> tuple[list[ScoredChunk], str | None]
  .is_low_confidence(chunks) -> bool
```

**任何 provider 异常都降级为上游顺序截断**，把原因放进返回的第二个值（`degraded`）。重排序失败绝不能让问答整体失败。`enabled=False` 返回 `degraded="rerank_disabled"`。

### 4.7 `retrieval/hybrid.py`

```python
HybridRetriever(vectorstore, bm25, reranker)
  .search(query, mode="hybrid_rerank", top_k=5) -> RetrievalResult
build_retriever(storage_dir=None) -> HybridRetriever   # lru_cache，供 Streamlit 复用
```

| `mode` | 流程 | 用途 |
|---|---|---|
| `vector` | 向量 top-20 → 截断 | 朴素 RAG 基线 |
| `hybrid` | 向量 top-20 + BM25 top-20 → RRF → 截断 | 验证关键词通道增益 |
| `hybrid_rerank` | hybrid 候选 → rerank → top-5 | **生产默认** |

**降级矩阵**：

| 触发 | `degraded` |
|---|---|
| 库为空 | `empty_knowledge_base` |
| embedding 服务故障 | `embedding_failed_fallback_bm25` |
| rerank 故障 | `rerank_failed: {原因}` |
| rerank 关闭 | `rerank_disabled` |
| rerank 返回空 | `rerank_empty` |

### 4.8 `generation/prompts.py`

```python
RAG_SYSTEM_PROMPT: str
NO_CONTEXT_PROMPT: str
build_rag_messages(question, chunks, max_context_tokens) -> tuple[list[dict], list[Citation]]
extract_citation_indices(answer: str) -> list[int]     # 正则 \[\d{1,3}\]
validate_citations(answer, valid: set[int]) -> tuple[str, list[int]]
```

上下文拼接规则：
1. 按 `rank` 升序（相关性降序）——对抗 LLM 的「lost in the middle」；
2. 引用编号从 1 开始，与返回的 `citations` 下标严格一致；
3. 逐条累加 `estimate_tokens`，**超预算即停止，不截断单条**——保留完整语义块比塞半句更有价值；
4. 编号在拼接时即固定，生成后无需二次匹配。

### 4.9 `generation/rag.py`

```python
RAGEngine(retriever, llm=None, settings=None)
  .stream_answer(question, mode=None, history=None) -> Iterator[StreamEvent]
  .answer(question, mode=None) -> AgentResult
  .retrieve_only(question, mode=None) -> RetrievalResult
```

**事件序列契约（前端依赖，顺序不可变）**：

| 序 | 事件 | 说明 |
|---|---|---|
| 1 | `{"type": "degraded", "reason": str}` | 仅降级时，**必须在 token 之前** |
| 2 | `{"type": "citations", "citations": [...]}` | |
| 3 | `{"type": "token", "text": str}` | 0..N 个 |
| 4 | `{"type": "usage", "prompt_tokens", "completion_tokens"}` | |
| 5 | `{"type": "error", "message": str}` | 仅失败时 |
| 6 | `{"type": "done", "answer", "degraded", "latency_ms"}` | **永远是最后一个** |

**任何失败都不能让生成器抛出**：LLM 异常转成 `error` 事件后仍以 `done` 收尾。`retrieve_only` 绝不调用 LLM。

### 4.10 `generation/cache.py` / `fallback.py`

```python
SemanticCache(embedder, cache_dir, threshold)
  .get(question) -> AgentResult | None    # 余弦 ≥ threshold 命中
  .put(question, result)                  # 相同问题原地更新 hit_count
  .save() / .load() / .size() / .clear()

decide(retrieval: RetrievalResult, answer: str) -> tuple[bool, str | None]
```

缓存阈值默认 **0.95**（偏高是刻意的）：问答场景下「差一点」的问题答案可能完全不同（「BERT 用了什么数据集」vs「BERT 用了什么优化器」，余弦可高但答案无关）。**召回不足比答错更可接受。**

降级判定优先级：无 chunks → `NO_HIT_NOTICE`；有上游 `degraded` → 透传；`chunks[0].score < min_relevance` → `LOW_CONFIDENCE_NOTICE`；答案为空 → 提示重试。

### 4.11 `agent/tools/base.py`

```python
@dataclass
class Tool:
    name: str; description: str; parameters: dict
    func: Callable[..., str]      # 只接受关键字参数，返回值强制 str
    timeout_s: float = 30.0

register_tool(name, description, parameters, timeout_s=30.0)   # 装饰器
build_registry() -> dict[str, Tool]
tools_description() -> str        # 拼进 System Prompt，按名字排序保证稳定
```

`build_registry` 用 `importlib.import_module` 逐个导入 8 个工具模块，**只捕获 `ImportError`** 并 `logger.debug` 后跳过。理由：工具是插件注册表，某个工具缺失或写坏不应该让整个 Agent 崩掉。

**8 个工具**：

| 工具 | 参数 | 说明 |
|---|---|---|
| `kb_search` | `query, top_k, mode` | 核心工具，封装 RAG 检索 |
| `paper_meta` | `doc_id?, filename?` | 论文元信息 |
| `paper_compare` | `doc_id_a, doc_id_b, aspect` | 两篇论文对比 |
| `extract_keywords` | `text, top_n` | 关键词提取 |
| `summarize_paper` | `doc_id` | 结构化摘要（背景-方法-结果-结论） |
| `calculator` | `expression` | **AST 白名单安全求值** |
| `current_time` | 无 | 当前时间 |
| `web_search` | `query, max_results` | DuckDuckGo，失败可读降级 |

**`calculator` 的安全设计**：绝不用裸 `eval`。两层防线——(1) `ast.parse(mode="eval")` 后遍历 AST，白名单放行 `Expression/BinOp/UnaryOp/Constant/Add/Sub/Mult/Div/Pow/Mod/USub/UAdd/FloorDiv`，拒绝 `Call/Attribute/Name`；(2) `eval(compile(tree, ...), {"__builtins__": {}}, {})`。`__import__('os').system(...)`、`(1).__class__`、`open('x')` 全部抛 `ValueError`。

### 4.12 `agent/react.py` —— 手写 ReAct

```python
class ActionParseError(Exception): ...
parse_action(raw: str) -> tuple[str, str, dict]
ReActAgent(llm, tools, max_iterations=6, tool_timeout_s=30.0, executor=None)
  .run(question, history=None) -> AgentResult
```

**文本协议**（不用 function calling，轨迹可读、兼容性好）：

```
Thought: 我需要先查知识库里关于 BERT 微调策略的内容
Action: kb_search
Action Input: {"query": "BERT 微调 策略", "top_k": 5}
Observation: [1] (bert.pdf 第7页) 我们使用了 AdamW ...
```

**解析容错**（三层）：
1. thought 可缺省；action 缺失即抛 `ActionParseError`；
2. 支持中英文冒号与关键字（`Thought|思考`、`Action|行动`、`Action Input|行动输入`）；
3. JSON 失败时先尝试给裸键补引号（`{expression: 1+1}` → `{"expression": "1+1"}`）再解析，仍失败才抛错。

**三个终止条件**（防死循环）：
1. 显式 `Action: Finish`；
2. **重复调用检测**——`(action, json.dumps(args, sort_keys=True))` 第二次出现即判定 `loop_detected`；
3. **轮次上限**——`max_iterations` 耗尽判 `max_iterations_reached`。

另有**连续 3 次解析失败**判 `parse_failed`。三种异常终止都走 `_force_conclude`，且 `_force_conclude` 自身失败时用已收集的 Observation 兜底，保证 `run()` **永不抛异常、answer 永非空**。

**错误即 Observation**：未知工具、工具超时、工具抛异常，一律转成可读 Observation 交还给 Agent，让它自行换策略——这正是 ReAct 自愈能力的关键。

### 4.13 `agent/router.py` / `executor.py` / `memory.py`

```python
classify(question) -> RouteDecision(kind, tool, args, reason)   # kind ∈ {direct_tool, agent}

ToolExecutor(tools, timeout_s=30.0, max_workers=4)
  .run_one(tool, args) -> str                     # 超时/异常均返回可读字符串
  .run_parallel(calls) -> list[str]               # 输出顺序与输入一致

ConversationMemory(max_tokens=2000, summarize_after_turns=8, llm=None, store_dir=None)
  .new_session() / .get(sid) / .append(sid, turn) / .clear(sid)
  .build_context(sid) -> tuple[list[dict], str | None]
  .list_sessions() / .save(sid) / .load(sid)
```

**路由的严格性**：算术判定必须真正含运算符，`"3.14"` 这种纯数字判为 `agent`（否则会把普通问题误当算式）。时间类判定要求长度 < 30，避免长篇问题被误判。

**记忆三层机制**：会话隔离（`session_id`）→ 滑动窗口 Token 控制（**按整轮裁剪**，不切断 user/assistant 配对）→ 超阈值摘要压缩（**滚动摘要**，且结果缓存，不重复摘要）。

### 4.14 `observability/`

```python
TraceRecorder(log_dir)  .record(result, session_id) / .read_recent(n=50)
compute(result) -> dict
aggregate(records) -> dict
health_check(retriever, llm, timeout_s=5.0) -> dict[str, tuple[bool, str]]
render_trace_tree(steps) -> str
```

`record` 用 `json.dumps(..., default=str)`——`default=str` 让任何不可序列化对象降级成字符串而不是抛 `TypeError`；整体再包一层 try/except。**观测失败绝不能影响主流程。**

`health_check` 每个探测独立 try/except，LLM 探测用守护线程 + `Event.wait(timeout)` 限时（不用 `ThreadPoolExecutor`：它的 shutdown 会等挂死线程，超时形同虚设）。

## 8. 已知限制

1. **单机单用户**：无鉴权，会话靠 `session_id` 区分，多人同时用会互相覆盖。
2. **扫描件 PDF 无法处理**：PyMuPDF 抽不出图片型 PDF 的文字，需先 OCR。
3. **Streamlit 状态模型**：每次交互重跑整个脚本，所有可变状态必须在 `st.session_state`，重资源必须 `@st.cache_resource`。
4. **中文分词用 bigram**：不引入 jieba 以保持零额外依赖，代价是 BM25 的精确率略低于分词方案；在 `hybrid` 模式下由向量通道互补。
5. **语义缓存为线性扫描**：万级条目以下耗时可忽略，更大规模需换向量索引。
